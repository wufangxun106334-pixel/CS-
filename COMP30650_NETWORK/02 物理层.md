# 物理层

对应课件：`L4` `L5`

## 1. 物理层的核心问题

网络里真正传播的不是抽象的“message”，而是介质中的信号 `signal`。

所以物理层解决的是：

**如何把 bit 变成能在介质上传输的信号。**

## 3. 关键指标

### Bandwidth 带宽

- 表示吞吐能力，不直接等于“快到达”
- 带宽高不代表传播时延低

### 计算只抓两个要点

#### 要点 1：Latency 计算

考试给 frame/message size、bandwidth、distance、propagation speed 时：

```text
Transmission delay = message size / bandwidth
Propagation delay  = distance / propagation speed
Latency            = transmission delay + propagation delay
```

关键是单位统一：

```text
bytes -> bits:       bytes * 8
Mbps  -> bits/s:     Mbps * 10^6
km    -> m:          km * 1000
```

Transmission delay 计算过程：
```

完整 Latency 例题：

```text
distance = 35000 km = 35,000,000 m
propagation speed = 2 * 10^8 m/s

Propagation delay = 35,000,000 / (2 * 10^8)
                  = 0.175 s
                  = 175 ms

Latency = Transmission delay + Propagation delay
        = 0.144 ms + 175 ms
        = 175.144 ms
```

#### 要点 2：BDP 计算

`BDP` 表示链路中“已经发送出去、但还在路上”的数据量，也就是 link pipe 里能同时容纳多少 bit。

```text
BDP = Bandwidth * Delay
```

单位：

```text
Bandwidth: bits/s
Delay:     s
BDP:       bits
```

如果问单向 link 上有多少 data in flight：

```text
BDP = transmission rate * propagation delay
```

如果问 TCP / sliding window 要多大才能填满链路：

```text
required window size ≈ bandwidth * RTT
```

BDP 和 data size 的关系：

```text
BDP 本身 = bandwidth * delay
data size 不参与 BDP 本身计算

data size 用来算：
number of messages/frames in flight = BDP / message size
```

换句话说：

- `bandwidth` 决定每秒能把多少 bits 推进链路。
- `delay` 决定这些 bits 会在链路里停留多久。
- `BDP` 是链路这根 pipe 里能装多少 bits。
- `data size` 只是用来把 BDP 从 bits 换算成“能装几个 frame/message”。

BDP 例题：

```text
R = 10 Mbps = 10 * 10^6 bits/s
Dprop = 50 ms = 0.05 s

BDP = 10 * 10^6 * 0.05
    = 500,000 bits
    = 62,500 bytes
```

如果每个 message 是 `1250 bytes`：

```text
message size = 1250 * 8 = 10,000 bits
number of messages in flight = 500,000 / 10,000 = 50
```

对比记忆：

| 要算什么               | 需要 bandwidth 吗                      | 需要 data size 吗                      | 公式                                       |
| ------------------ | ----------------------------------- | ----------------------------------- | ---------------------------------------- |
| transmission delay | yes                                 | yes                                 | `data size / bandwidth`                  |
| propagation delay  | no                                  | no                                  | `distance / propagation speed`           |
| latency            | yes, if includes transmission delay | yes, if includes transmission delay | `transmission delay + propagation delay` |
| BDP                | yes                                 | no                                  | `bandwidth * propagation delay`          |
| messages in flight | yes, via BDP                        | yes                                 | `BDP / message size`                     |

考试意义：

- BDP 大时，`stop-and-wait` 效率低，因为 sender 每次只允许 1 个 frame outstanding。
- sliding window / TCP window 需要足够大，才能让链路一直保持 busy。
- BDP 不是 latency；BDP 是“容量/在途数据量”，latency 是“时间”。

## 5. Modulation / Encoding 调制与编码

### 为什么需要它

因为计算机处理的是 0 和 1，但物理世界只能传输信号变化。

### 典型方案

- `[NRZ]()`
- `NRZI`
- `Manchester Encoding`
- `4B/5B`
- `Passband Modulation`

### 核心理解

- 编码不是为了“让 bit 更数学化”
- 而是为了让接收方更稳定地识别 bit 边界与值

### Manchester Encoding

课件强调：

- 用 `transition` 而不是静态电平来表示 bit
- 原始 bit stream 会与 clock signal 做 XOR
- 时钟频率是 bit rate 的两倍

这样做的价值是更容易做 [[02 物理层#6. Clock Recovery 时钟恢复]]。

### 4B/5B

课件中的重点不是死记码表，而是理解目标：

- 把每 4 个 data bits 映射成 5 个 code bits
- 避免出现太长的 0 串
- 常与 `NRZI` 一起讨论，帮助打破长串重复信号

### Passband Modulation

课件总复习页明确把它列为物理层重点。

如果不是直接在 baseband 上送信号，就需要先借助 carrier signal。
典型能被修改的 carrier 元素有：

- amplitude 幅度
- frequency 频率
- phase 相位

详见 [[概念/Passband Modulation 与 Carrier]]。

### QAM

`QAM = Quadrature Amplitude Modulation`

它把 amplitude 和 phase 组合起来，让一个 symbol 表达多个 bits。

| Scheme | Symbols | Bits per symbol |
|---|---:|---:|
| BPSK | 2 | `1` |
| QPSK | 4 | `2` |
| QAM-16 | 16 | `4` |
| QAM-64 | 64 | `6` |

计算规则：

`bits per symbol = log2(symbol count)`

意义：

- 更高 bits/symbol 可以提高频谱效率
- 但 constellation 点更密，通常要求更高 SNR
- 信道噪声大时，高阶 QAM 更容易判错

### Baseband vs Passband

| 维度    | Baseband                     | Passband                              |
| ----- | ---------------------------- | ------------------------------------- |
| 基本思路  | 直接在介质上传输基带信号                 | 用 carrier 承载信息                        |
| 常见上下文 | NRZ, NRZI, Manchester, 4B/5B | radio, wireless, cable/fiber passband |
| 可调对象  | 电平/跳变/编码规则                   | amplitude, frequency, phase           |
| 适用直觉  | 短距离/有线链路常见                   | 需要把信号搬到适合传播的频段                        |


## 6. Clock Recovery 时钟恢复

如果信号长时间不变，接收端难以判断 bit 边界。

所以某些编码方案比简单的 NRZ 更适合实际通信。

课件里对应的设计思路包括：

- `NRZI`：用 1 触发翻转
- `Manchester`：强制每 bit 周期出现过渡
- `4B/5B`：避免长串 0

## 7. 与其他层的联系

- 物理层上传输的是 `bit`
- [[03 链路层]] 把 bit 组织成 `frame`
- [[04 网络层]] 关心的是更高一级的 `packet`

也就是：
physics,        link,         network,      transport,   application
`signal -> frame -> packet -> segment -> message`

## 8. 易错点辨析

### 易错 1：Bandwidth 就是速度，所以 bandwidth 越大延迟一定越小

不对。

带宽主要影响 transmission delay，不直接决定 propagation delay。

### 易错 2：物理层已经负责可靠传输

不对。

可靠性往往主要在 [[03 链路层]] 和 [[05 传输层]] 里处理。

### 易错 3：调制只有“把信号变强一点”这一种操作

不对。

课件明确区分了可调 carrier 的多个维度：幅度、频率、相位。
