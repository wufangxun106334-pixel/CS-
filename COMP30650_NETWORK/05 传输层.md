# 传输层

对应课件：`L15`

## 1. 传输层的地位

传输层是应用和网络之间的关键桥梁。

它不直接决定经过哪些 router，也不处理本地 MAC 转发；它关心的是：

**两个应用进程之间，数据该以什么服务质量被送达。**

详见 [[概念/TCP、UDP 与 QUIC]]。

## 3. Socket 与 Port

### Socket 套接字

- 是应用使用网络的抽象接口
- 可视为通信端点 `endpoint`

### Port 端口

- 标识主机上的具体应用进程
- 常与 IP、协议类型一起使用

这一层才真正把“送到哪台主机”进一步细化成“送到哪一个应用”。

### 常见端口与头部

| 项目                 | 高频记忆                                       |
| ------------------ | ------------------------------------------ |
| HTTP server        | TCP port `80`                              |
| HTTPS server       | TCP port `443`                             |
| DNS                | 通常 UDP port `53`，大型响应/zone transfer 可用 TCP |
| DHCP server/client | UDP `67/68`                                |
| TCP header         | 最小 `20 bytes`，通常比 UDP header 大             |
| UDP header         | `8 bytes`                                  |
|                    |                                            |

IPv4 header 里有 `TTL`, `Protocol`, `Source IP`, `Destination IP`，
但没有 Destination **Port**`；port 属于 transport layer header。

## 4. TCP、UDP、QUIC

详见 [[概念/TCP、UDP 与 QUIC]]。

先抓住高频对比：

| 协议   | 特征                 | 典型场景                  |
| ---- | ------------------ | --------------------- |
| TCP  | 可靠、有序、**面向连接**、字节流 | Web、文件传输              |
| UDP  | 轻量、无连接、消息导向        | **DNS**、**VoIP**、DHCP |
| QUIC | 基于 UDP，强调现代性能      | **HTTP**/3            |

## 5. Connection Establishment 建立连接

TCP 要先建立连接，是因为双方需要：

- 都处于 ready 状态
- 协商参数
- 同步初始序号
- 建立端点状态

### Three-Way Handshake 三次握手

1. `SYN`(递增)
2. `SYN + ACK`
3. `ACK`(对方SYN,每轮递增)
Client                                      Server

SYN, Seq = x
----------------------->

SYN + ACK, Seq = y, Ack = x + 1
<----------------------

ACK, Seq = x + 1, Ack = y + 1
------------------------>

## 6. Connection Release 连接释放

常见记忆法：

- `Four-way handshake / 四次挥手` 双方都要确认FIN和ACK才关闭通道
- 
Client                                              Server

ESTABLISHED                                ESTABLISHED
FIN_WAIT_1  ---- FIN --------------------> CLOSE_WAIT
FIN_WAIT_2  <--- ACK --------------------- CLOSE_WAIT(有可能没传完)
TIME_WAIT   <--- FIN --------------------- LAST_ACK (传完了)
TIME_WAIT   ---- ACK --------------------> CLOSED
CLOSED

要点：

- TCP 是有状态连接
- 释放连接也需要显式同步状态

## 7. Sequence Numbers 与 ACK

### Sequence Numbers

- 表示字节流中的位置
- 用于保证有序与可重传

### ACK

- 接收方确认哪些数据已经收到
- 与重传机制配合

## 8. Flow Control 流量控制

流量控制不是“控制整个互联网拥塞”，而是：

**让发送方不要快到把接收方压垮。**

它面向的是 sender 和 receiver 之间的处理能力匹配。

## 9. Sliding Window 滑动窗口

滑动窗口的意义：

- 不必一发一等
- 允许多个 segment 在途
- 提高链路利用率

这与 [[02 物理层#3. 关键指标]] 里的带宽时延积概念能联系起来看。

## 10. 与应用层的关系

- [[概念/DNS、HTTP 与 HTTPS#DNS Domain Name System]] 可使用 UDP
- [[概念/DNS、HTTP 与 HTTPS#HTTP HyperText Transfer Protocol]] 通常依赖 TCP 或 QUIC
- HTTPS 常建立在 TLS 之上，再跑在 TCP 上

## 11. 易错点辨析

### 易错 1：TCP 可靠，所以应用层就不用设计了

不对。

TCP 解决的是通用传输问题，不等于应用语义问题自动消失。

### 易错 2：UDP 一定更差

不对。

UDP 是功能更少，不是一定更差；在低时延、应用自控场景反而合适。

### 易错 3：流量控制就是拥塞控制

不完全对。

课程中首先要分清：

- `flow control` 面向接收方能力
- `congestion` 面向网络承载状态

### 易错 4：三次握手只是形式流程

不对。

三次握手直接关系到状态建立和序号同步，是可靠传输的起点。
