# 堆（Heap）

## 一、什么是堆

堆是一种**完全二叉树**，满足 **堆序性质**：
- **小顶堆（Min Heap）**：每个父节点 ≤ 它的两个子节点
- **大顶堆（Max Heap）**：每个父节点 ≥ 它的两个子节点

堆只保证**纵向有序**（根到叶子的路径单调），**不保证横向有序**（兄弟节点之间大小随意）。

```
        ①              ← 全局最小值
       /  \
      ③    ②           ← 兄弟之间 ③ > ② 无所谓
     / \   / \
    ⑦  ⑨ ⑤  ⑥        ← 叶子之间更随意
```

### 二叉堆 vs 二叉搜索树（BST）

| 性质 | 小顶堆 | 二叉搜索树 |
|------|-------|-----------|
| 父与子 | 父 ≤ 左右子 | 父 ≥ 左子，父 ≤ 右子 |
| 左与右 | **不要求** | **左子树 < 根 < 右子树** |
| 核心用途 | 快速找最值 | 快速查找/排序 |


## 二、数组存储与下标公式

堆用数组存储，利用完全二叉树的性质通过下标定位父子节点。

```
数组：[①, ③, ②, ⑦, ⑨, ⑤, ④]
       ↑
     index 0 = 根
```

下标公式（从 0 开始）：
- **左子节点**：`left = 2 × index + 1`
- **右子节点**：`right = 2 × index + 2`
- **父节点**：`parent = (index - 1) / 2`


## 三、核心操作

### 插入（push）— 上浮（bubble up / heapify_up）

1. 新元素放到数组末尾（树的最后一个位置）
2. 不断和父节点比较
3. 如果违反堆序 → 交换
4. 一直向上直到满足堆序或到达根

**时间复杂度：O(log n)** — 路径长度 = 树高

```
插入 2 到小顶堆 [1, 3, 5, 7, 9]：

        ①                 ①                ①
       / \               / \              /  \
      ③  ⑤      →      ③  ⑤      →     ③   ②
     / \  /            / \  /           / \  / \
    ⑦ ⑨ 2            ⑦ ⑨ ⑤          ⑦ ⑨ ⑤
                        ↑                    ↑
                     2 上浮              到达合法位置
```

### 删除最小/最大值（pop）— 下沉（sink down / heapify_down）

1. 保存堆顶（要返回的最值）
2. 把最后一个元素移到堆顶
3. 从堆顶开始下沉：
   - 找出当前节点和左右子节点中的最值
   - 如果最值不是自己 → 交换，继续从交换位置下沉
4. 返回原来的堆顶

**时间复杂度：O(log n)**

```
删除小顶堆最小值 ①：

        ①                 ⑨                 ③
       / \               / \               / \
      ③  ②      →      ③  ②      →      ⑨  ②
     / \ / \           / \ / \           / \ / \
    ⑦ ⑨⑤ ④          ⑦ ⑨⑤ ④          ⑦ ⑨⑤ ④
                            ↑                    ↑
                        ⑨ 移到根              下沉一层
                        
        ③                 ③
       / \               / \
      ⑤  ②      →      ⑤  ④       ← 堆序恢复 ✅
     / \ / \           / \ /
    ⑦ ⑨④            ⑦ ⑨②
```

### 查看堆顶（peek）

直接返回 `heap[0]` — **O(1)**


## 四、堆和冒泡排序的类比

堆的插入（上浮）和删除（下沉），本质是在二叉树上做**受限版冒泡**——每一步只和相邻的父/子节点比较、交换。

| 操作 | 冒泡排序 | 堆的上浮/下沉 |
|------|---------|-------------|
| 比较对象 | 相邻元素 | 父子节点（逻辑上相邻） |
| 交换条件 | 逆序 | 违反堆序 |
| 移动方向 | 单向推进 | 沿树路径逐层推进 |
| 复杂度 | O(n²) | **O(log n)** |

**为什么堆更快？** 堆利用了树形结构，将"冒泡路径"从 O(n) 缩短到 O(log n)。


## 五、堆与栈的对比

| | 栈（Stack） | 堆（Heap / PriorityQueue） |
|---|-----------|--------------------------|
| 出队顺序 | **插入时间**决定（LIFO） | **元素大小**决定（优先级） |
| 能否干预 | ❌ 后进先出，不可控 | ✅ 控制插入的值就能控制出队顺序 |
| 别名 | — | **优先队列（Priority Queue）** |


## 六、堆和 DFS 的关系

- **堆的下沉/上浮不是 DFS** — 它是贪心路径选择，一次只走一条路，不回溯、不穷举
- **建堆（heapify）的从下往上顺序** 是后续遍历（post-order）的顺序 — 这部分确实用了 DFS 的遍历思想


## 七、建堆（Heapify）

### 为什么从子到父建堆？

**核心原因：** 下沉操作（sink）的前提是左右子树已经是合法堆。

**从下往上建堆：**
1. 从最后一个非叶子节点开始（index = n/2 - 1）
2. 从后往前，每个节点执行一次下沉
3. 每个节点下沉时，它的左右子树已经是合法堆

**时间复杂度的直觉分析：**

大部分节点在树的下层，下沉距离短：

| 层数 | 节点数 | 下沉距离 | 总操作 |
|------|-------|---------|-------|
| 0（根） | 1 | h | 1×h |
| 1 | 2 | h-1 | 2×(h-1) |
| 2 | 4 | h-2 | 4×(h-2) |
| … | … | … | … |
| h-1 | n/2 | 0 | 0 |

总和 ≈ **O(n)**

**复杂度：O(n)**（数学上该级数收敛到 O(n)）

### 为什么从上往下建堆是错的？

从上往下建堆时，下沉时子树尚未合法，可能出现：
- 根节点满足条件就停止下沉
- 但子树内部仍然不符合堆序
- 需要反复回头修，复杂度退化为 O(n log n)

```
        ①         ← 根比两个孩子都小，下沉不动了
       /  \           但子树内部可能还是乱的！
      ②    ⑨
     / \   / \
    ③  ⑤ ⑧  ④    ← ⑨ > ⑧，违反了堆序！
```


## 八、Java 实现（小顶堆）

```java
class MinHeap {
    ArrayList<Integer> heap;
    int size;

    public MinHeap() {
        this.heap = new ArrayList<>();
        this.size = 0;
    }

    public void push(int x) {
        heap.add(x);
        size++;
        heapify_up(size - 1);
    }

    public Integer pop() {
        if (size == 0) return null;

        int temp = heap.get(0);
        heap.set(0, heap.get(size - 1));
        heap.set(size - 1, temp);

        size--;
        heapify_down(0);

        return heap.remove(heap.size() - 1);
    }

    public int peek() {
        return heap.get(0);
    }

    public void heapify_up(int index) {
        int parent = (index - 1) / 2;
        if (index > 0 && heap.get(index) < heap.get(parent)) {
            int temp = heap.get(index);
            heap.set(index, heap.get(parent));
            heap.set(parent, temp);
            heapify_up(parent);
        }
    }

    public void heapify_down(int index) {
        int left = 2 * index + 1;
        int right = 2 * index + 2;
        int smallest = index;

        if (left < size && heap.get(left) < heap.get(smallest)) {
            smallest = left;
        }
        if (right < size && heap.get(right) < heap.get(smallest)) {
            smallest = right;
        }

        if (smallest != index) {
            int temp = heap.get(index);
            heap.set(index, heap.get(smallest));
            heap.set(smallest, temp);
            heapify_down(smallest);
        }
    }
}
```

### 关键语法说明

| 方法 | 作用 | 是否改变数组长度 |
|------|------|---------------|
| `heap.add(x)` | 追加新元素到末尾 | ✅ 长度 +1 |
| `heap.set(i, x)` | **替换**下标 i 处的元素 | ❌ 长度不变 |
| `heap.get(i)` | 获取下标 i 处的元素 | ❌ |
| `heap.remove(i)` | 删除下标 i 处的元素 | ✅ 长度 -1 |
| `(index - 1) / 2` | 计算父节点下标 | — |
| `2 * index + 1` | 计算左子节点下标 | — |
| `2 * index + 2` | 计算右子节点下标 | — |

**`heapify_up` / `heapify_down` 传下标而非传值的原因：** 下标是树中的定位坐标，能直接算出父子位置；值不包含位置信息，交换后无法继续递归。
	

## 九、堆能排序吗？—— 堆排序（Heap Sort）

堆虽然不维护左右顺序，但每次都能从堆顶拿到全局最值——这就够了。

**步骤：**

1. **建堆**（O(n)）— 把所有元素建成合法的堆
2. **反复取堆顶 + 重建堆**（O(log n) 每次）— 取 n 次 → O(n log n)

```
原始数组：[4, 9, 3, 5, 1, 7]

建堆（小顶堆）：[1, 4, 3, 9, 5, 7]
取出 1 →       [3, 4, 7, 9, 5]     排好：1
取出 3 →       [4, 5, 7, 9]         排好：1, 3
取出 4 →       [5, 9, 7]           排好：1, 3, 4
取出 5 →       [7, 9]              排好：1, 3, 4, 5
取出 7 →       [9]                 排好：1, 3, 4, 5, 7
取出 9 →                           排好：1, 3, 4, 5, 7, 9 ✅
```

**总复杂度：O(n log n)**

### 三种排序对比

| 排序 | 每次取最小值的代价 | 总复杂度 |
|-----|-------------------|---------|
| **选择排序** | 扫描整个数组找最小 → O(n) | O(n²) |
| **归并排序** | 不按"取最小"思路工作 | O(n log n) |
| **堆排序** | O(log n)（只用父子比较） | **O(n log n)** |


## 十、堆的性质总结

- **局部有序**：每条根到叶子的路径单调，但兄弟之间、子树之间完全无序
- **这个"局部"刚好够用**：找最值只看根（O(1)），修复堆序只走一条路径（O(log n)）
- **放弃左右比较不是缺陷，而是让堆变快的关键设计决策**
