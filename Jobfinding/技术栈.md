# 都柏林 IT 求职路线与技术栈规划

## 一、核心判断

当前最稳妥的求职策略是“双轨并行，但资源向 TPM / Tech Analyst 倾斜”。

- 主线：TPM / Technical Project Manager / Tech Analyst
- 副线：Graduate Developer Programme
- 核心优势：UCD Computer Science 硕士 + 3 年制造业项目管理经验 + 2 年 Stamp 1G 签证
- 核心打法：不和纯科班生硬拼 LeetCode 数量，而是放大项目管理、交付经验、业务理解和技术常识

9 月到 11 月是爱尔兰美企和跨国企业 Graduate Programme 秋招黄金期。11 月到 12 月可以同步冲刺 TPM 全职岗位，目标是在次年 1 月无缝入职。

## 二、8 周核心卡位学习计划

### 第 1-3 周：战略卡位与技术包装

目标：拿到 IT 行业入场券，重组简历。

#### 1. AWS Cloud Practitioner

用途：

- 证明具备云原生项目常识
- 为 TPM 简历增加技术可信度
- 面试时能听懂 EC2、S3、RDS、IAM、VPC、CloudWatch 等基础概念

执行方式：

- 学习 AWS Cloud Practitioner Essentials 官方课程
- 使用 Coursera、YouTube 或 AWS Skill Builder
- 第 3 周前完成认证或至少完成系统学习
- 证书放到 LinkedIn 和简历靠前位置

#### 2. Jira 与敏捷流程

用途：

- 建立 TPM / Scrum Master / Tech Analyst 的工具能力
- 把过去制造业项目经验迁移到 IT 研发流程语言中

必须掌握：

- 创建 Project
- 配置 Kanban / Scrum Board
- 编写 User Story
- 管理 Epic、Task、Bug
- Sprint Planning
- Daily Standup
- Sprint Review
- Retrospective
- Risk / Dependency tracking

学习方式：

- 注册免费 Jira 账号
- 搜索 Jira cloud tutorial for project managers
- 自己模拟一个软件项目看板

#### 3. 简历准备两版

版本 A：TPM / Tech Analyst 冲刺版

重点放大：

- 3 年制造业项目管理经验
- 敏捷、精益、交付、风险控制、跨部门协作
- UCD Computer Science 硕士
- AWS 基础
- Jira / SQL / Git / Docker 基础
- 项目交付、进度管理、资源协调、供应商管理

版本 B：Graduate Developer 随缘版

重点放大：

- Python / Java / SQL / Web 项目
- UCD 课程项目
- GitHub 链接
- LeetCode 75
- 基础算法与数据结构
- Docker / AWS 部署经历

### 第 4-6 周：项目实战与履历镀金

目标：利用 UCD Practicum / 毕设打造一个工业级商业项目。

#### 1. 主动承担 Scrum Master / Technical Lead

在组队项目中主动承担：

- Sprint Planning
- Daily Standup
- Jira / Trello 任务管理
- 项目进度跟踪
- 风险识别
- 需求优先级排序
- 团队沟通协调

这段经历可以直接转化为 TPM 面试故事。

#### 2. 技术上引入云和容器

即使项目本身较简单，也尽量加入：

- Docker
- GitHub Actions
- AWS Free Tier
- PostgreSQL / MySQL
- 基础 API 设计
- 简单监控或日志

最终目标：

- Dev 面试可以讲代码、数据库、部署
- TPM 面试可以讲团队协作、需求管理、风险控制、敏捷交付

### 第 7-8 周：面试冲刺与真题演练

目标：建立 STAR 故事库，保持代码手感，打通内推渠道。

#### 1. STAR 故事库

准备 5 个真实故事：

- 3 个来自国内制造业项目管理经历
- 2 个来自 UCD 团队项目 / Practicum

必须覆盖：

- Conflict Resolution：团队意见不合、研发和业务冲突如何解决
- Risk Management：项目延期时如何重新排期、砍需求、控风险
- Growth Mindset：失败项目、遗憾项目、复盘和改进
- Stakeholder Management：如何协调不同部门、供应商或团队成员
- Delivery Ownership：如何推动项目按时交付

#### 2. LeetCode 维护

不追求刷新题数量。

每天 30-45 分钟复习：

- LeetCode 75 错题
- 哈希表
- 双指针
- 栈和队列
- 二叉树遍历
- BFS / DFS
- 基础动态规划

目标是保持手感，防止 Graduate Dev 面试时完全生疏。

#### 3. Networking / Referral

LinkedIn 搜索关键词：

```text
UCD Computer Science alumni Dublin
```

重点找：

- Amazon / AWS
- TikTok
- HubSpot
- Workday
- SAP
- Mastercard
- Google
- Meta
- Salesforce

私信方向：

- 表明自己是 UCD Computer Science 在读学生
- 说明计划申请 Graduate Programme 或 TPM / Tech Analyst
- 请教面试经验
- 在建立联系后再询问是否方便 referral

## 三、9 月后的求职时间线

### 9 月 - 11 月：秋招主战场

主攻 Graduate Programme：

- AWS
- Workday
- SAP
- HubSpot
- TikTok
- Mastercard
- Google
- Meta
- Salesforce

特点：

- 流程较长，通常 3-4 轮
- 看学校背景、潜力、基础能力、STAR 故事
- Dev 岗会考算法、基础工程、项目经验

同步投递 TPM / Tech Analyst：

- 中大型企业
- 咨询公司
- 工业 IT
- 金融科技
- 数字化转型团队

特点：

- 流程相对快，可能 2-3 周完成
- 更看重 3 年项目管理经验、英文沟通、交付能力和 1G 签证可立即入职

### 11 月 - 12 月：TPM 全职冲刺

重点话术：

```text
My academic modules will be completed in December, and I will be available to start full-time from January. With my Stamp 1G permission, the company does not need to sponsor a work permit immediately, so I can join without visa-related delay or risk.
```

中文含义：

我的课程模块 12 月结束，1 月可以全职入职。因为我有 Stamp 1G，企业不需要立刻承担工签担保和等待风险。

## 四、Junior Dev 与 TPM 薪资和路线对比

| 发展阶段 | Junior Developer | TPM / Technical Project Manager |
| --- | --- | --- |
| 起步薪资 | €40,000 - €55,000 | €55,000 - €70,000 |
| 3-5 年 | €60,000 - €85,000 | €75,000 - €100,000+ |
| 经验折现 | 过去制造业经验折现较弱 | 3 年项目管理经验可直接折现 |
| 签证匹配 | 需满足 Critical Skills 门槛 | IT Project Manager 更容易覆盖薪资门槛 |
| 竞争逻辑 | 和科班、实习、刷题选手硬拼 | 走复合背景、沟通和交付能力 |

核心判断：

- 如果走 Junior Dev，过去 3 年制造业经验很可能被当作非相关经验处理
- 如果走 TPM，可以把制造业项目经验包装成交付、风险、预算、供应商和跨部门管理能力
- TPM 起步薪资和谈判空间通常更好

## 六、都柏林开发岗位技术栈要求

### 1. Junior Developer

2026 年 Junior Dev 的基本要求已经不再是会语法和 CRUD，而是能独立交付完整功能模块。

必须具备：

- Python：FastAPI 或 Django
- Java：Spring Boot
- 前端：React / TypeScript
- Git / GitHub：Branch、Merge、Pull Request、冲突解决
- SQL：MySQL 或 PostgreSQL
- 数据库索引、外键、多表 Join
- AI 协同编程：Copilot / Cursor
- 能人工 Review AI 生成代码

面试测试点：

- 解释语言底层概念
- 修改 GitHub 仓库并提交 PR
- 写 SQL 多表联查
- Live Coding
- 解释 AI 生成代码的逻辑和风险

自查：

- 如果只跟网课写过 demo
- 数据库只用本地内存
- 不会 Git 冲突
- 没有独立部署经验

则距离都柏林 Junior Dev 上岸标准仍有 3-6 个月实战差距。

### 2. Mid-Level Developer

核心定义：不需要人带，拿到需求就能独立交付或带小团队攻坚。

必须具备：

- 微服务架构
- OOD / 设计模式
- RESTful API 最佳实践
- API 幂等性
- Docker
- AWS / Azure 部署
- CI/CD：GitHub Actions / Jenkins
- Redis
- RabbitMQ / Kafka
- pytest / JUnit
- 单元测试和集成测试

面试测试点：

- 系统设计
- 生产事故排查
- 内存溢出、服务崩溃、监控和恢复
- 缓存穿透、缓存雪崩
- 消息队列可靠性
- 测试覆盖率和工程质量

判断：

转码硕士加高强度自学，即使能做出 Docker + 前后端分离 + Redis 项目，也通常只是摸到 Mid-level 边缘。该级别通常需要 1-3 年商业项目经验。

### 3. Senior / Lead Developer

核心能力：

- 高可用分布式系统
- 多区域部署
- 云架构
- Terraform / Infrastructure as Code
- 网络安全
- GDPR 合规
- 数据库性能调优
- 架构决策
- 带新人
- 跨团队沟通

Senior 的代码时间可能只占 30%，更多时间用于架构、技术决策和沟通。

## 七、TPM 需要补齐的技术常识

TPM 不需要精通 Redis 调优、手写复杂算法或深入实现高并发系统，但必须能听懂工程团队的问题。

优先补齐：

- Web 应用基本架构：前端、后端、数据库、API
- Git / GitHub：分支、PR、版本发布
- Jira / Scrum / Kanban
- AWS 基础：EC2、S3、RDS、IAM、VPC、CloudWatch
- Docker 基础：镜像、容器、部署
- CI/CD 基础：构建、测试、部署流水线
- SQL 基础：表、Join、索引
- 系统设计常识：可用性、扩展性、性能、监控、日志
- 安全和合规常识：GDPR、权限、数据保护

面试表达重点：

- 我不替工程师写所有代码，但我能理解技术约束
- 我能把业务需求转成可交付的技术任务
- 我能识别风险、协调资源、管理依赖并推动交付
- 我能用过去制造业项目管理经验帮助技术团队提高执行效率

## 八、推荐行动优先级

最高优先级：

1. AWS Cloud Practitioner
2. Jira / Scrum 实操
3. 两版简历
4. 5 个 STAR 故事
5. UCD 项目中争取 Scrum Master / Technical Lead 角色
6. LinkedIn 内推网络

中等优先级：

1. Docker 基础
2. SQL 强化
3. Git / GitHub PR 流程
4. 一个可部署的 UCD 项目
5. LeetCode 75 错题复盘

低优先级：

1. LeetCode 500 题
2. 深入 Redis / Kafka 原理
3. 过度打磨个人网站
4. 无目标地刷课程
5. 追求所有技术都学到精通

## 九、最终路线建议

如果你极度热爱写代码，并愿意用半年以上时间高强度补齐工程能力，可以主攻 Developer。

如果你更擅长沟通、规划、控风险、协调资源，并且希望更快激活过去 3 年经验，那么 TPM / Tech Analyst 是胜率更高的路线。

最现实的策略：

- 简历双轨
- 投递双轨
- 学习资源向 TPM 倾斜
- 技术学习以“能听懂、能沟通、能判断风险”为目标
- UCD 项目包装成技术交付案例
- 9 月主攻 Graduate Programme
- 11 月和 12 月全力冲刺 TPM 全职
