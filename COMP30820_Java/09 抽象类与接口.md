## 4. abstract class vs interface

### abstract class 适合

- 抽取公共字段
- 抽取公共实现
- 建立类层次

### interface 适合

- 约束行为能力
- 支持一个类实现多种能力

## 5. Comparable 接口

来源示例：
- `lec_13_examples_2/ComparableGeometricObject.java`
- `test_3_code/Shape.java`
- `week11/prac_07_code/Intern.java`

### Demo

```java
public abstract class ComparableGeometricObject
        implements Comparable<ComparableGeometricObject> {
    @Override
    public int compareTo(ComparableGeometricObject o) {
        if (getArea() > o.getArea()) return 1;
        else if (getArea() < o.getArea()) return -1;
        else return 0;
    }
}
```

### 核心理解

- `Comparable<T>` 规定“同类如何比较”
- 返回值约定：
  - 正数：当前对象更大
  - 0：相等
  - 负数：当前对象更小

## 7. 易错点辨析

### 易错 1：抽象类里的方法都必须是抽象方法

不对。

抽象类可以同时有具体方法和抽象方法。

### 易错 2：接口可以保存复杂共享状态，和普通类一样

本课程复习里不这么理解。

接口核心是行为规范，不是共享实例状态。

### 易错 3：重写 `equals` 时参数可以写成子类类型

不对。

签名必须是：

```java
public boolean equals(Object obj)
```

## 8. 接口的隐式修饰符

接口中所有成员的修饰符是**自动隐式添加**的：

```java
// 👇 显式写法
public interface Edible {
    public static final int MAX_WEIGHT = 100;
    public abstract String howToEat();
}

// 👆 等价于以下简洁写法
public interface Edible {
    int MAX_WEIGHT = 100;    // 自动为 public static final
    String howToEat();       // 自动为 public abstract
}
```

### 易错点

- 接口中的变量默认是 `public static final` **常量**，不是普通变量
- 接口中的方法默认是 `public abstract`，不能有方法体（除非是 default/static 方法）

## 9. 接口的 default 和 static 方法 (Java 8+)

### default 方法（带默认实现）

```java
public interface Printable {
    void print();

    // default 方法：有方法体的接口方法
    default void printWithBorder() {
        System.out.println("================");
        print();
        System.out.println("================");
    }
}
```

- 实现类可以直接使用，也可以覆盖
- 解决了"给接口加新方法但不想破坏已有实现"的问题

### static 方法

```java
public interface MathUtils {
    static double square(double x) {
        return x * x;
    }
}

// 调用方式
MathUtils.square(4.0);  // 通过接口名调用
```

## 10. 接口可以扩展多个接口

```java
interface A { void methodA(); }
interface B { void methodB(); }

// 接口的多重继承
interface C extends A, B {
    void methodC();
}

// 实现 C 的类必须实现 A、B、C 中的所有方法
class MyClass implements C {
    public void methodA() { ... }
    public void methodB() { ... }
    public void methodC() { ... }
}
```

### 对比

| | 类 (class) | 接口 (interface) |
|---|---|---|
| 继承数量 | extends **一个** | extends **多个** |
| 被实现 | 被 extends 一个 | 被 implements **多个** |

## 11. 抽象类可以没有抽象方法

```java
// 合法！虽然没有抽象方法，但仍是抽象类，不能 new
public abstract class NoAbstractMethod {
    public void normalMethod() {
        System.out.println("这是一个普通方法");
    }
}
```

### 常见判断题陷阱

| 说法 | 对错 |
|------|------|
| "所有抽象方法必须在抽象类中" | ✅ 对 |
| "抽象类中所有方法都必须是抽象方法" | ❌ 错 |
| "抽象类不能有构造器" | ❌ 错 |
| "抽象类不能用作数据类型" | ❌ 错 |

## 12. ⭐ 跨层级多态案例：Animal/Fruit/Edible

这是接口最经典的用法：让**不同继承树**的类共享共同的行为。

```java
// === 接口：定义"可食用"行为 ===
interface Edible {
    String howToEat();
}

// === 抽象类：Animal（和 Fruit 在不同的继承树） ===
abstract class Animal {
    public abstract String sound();
}

class Chicken extends Animal implements Edible {
    public String sound() { return "cock-a-doodle-doo"; }
    public String howToEat() { return "Fry it"; }
    public String layEggs() { return "Lay eggs"; }
}

class Tiger extends Animal {  // 不实现 Edible
    public String sound() { return "RROOAARR"; }
}

// === 抽象类：Fruit（另一棵继承树） ===
abstract class Fruit implements Edible {
    // Fruit 不需要实现 howToEat()，留给子类
}

class Apple extends Fruit {
    public String howToEat() { return "Make apple pie"; }
}

class Orange extends Fruit {
    public String howToEat() { return "Make orange juice"; }
}
```

### 多态使用

```java
public class TestEdible {
    public static void main(String[] args) {
        Object[] objects = {new Tiger(), new Chicken(), new Apple(), new Orange()};

        for (Object o : objects) {
            if (o instanceof Edible) {
                System.out.println(((Edible) o).howToEat());
            }
            if (o instanceof Animal) {
                System.out.println(((Animal) o).sound());
            }
        }
    }
}
// 输出：
// RROOAARR
// Fry it
// cock-a-doodle-doo
// Make apple pie
// Make orange juice
```

### 关键理解

- `Edible` 是跨 Animal 和 Fruit 两个继承树的公共类型
- Chicken 和 Apple 没有任何继承关系，但都实现了 Edible → 都可以用 `Edible` 类型引用
- 这就是接口的真正威力：**给不同层次的类赋予共同能力**

## 13. OOP 三大支柱总结

| 支柱 | 含义 | Java 实现 |
|------|------|----------|
| **封装 (Encapsulation)** | 隐藏内部细节，只暴露接口 | `private` 字段 + public getter/setter |
| **继承 (Inheritance)** | 子类复用父类的属性和方法 | `extends` |
| **多态 (Polymorphism)** | 同一操作作用于不同对象有不同的行为 | 方法覆盖 + 动态绑定 |

- 抽象类和接口为**多态**提供了基础机制
- 封装 + 继承 + 多态 = 面向对象的核心
