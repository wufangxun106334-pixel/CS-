## 4. Sentinel Value 模式

来源示例：
- `lec_05_examples/SentinelValue1.java`

### Demo

```java
int sum = 0;
boolean isNeg = false;
while (!isNeg) {
    int number = input.nextInt();
    if (number != -1)
        sum += number;
    else
        isNeg = true;
}
```

### 核心理解

- `-1` 不是正常数据，而是“停止输入”的信号,初始值isNeg为负,保证连续输入,并且计算sum,一旦输入为-1,isNeg反转,终止循环.
- 这类题非常适合考循环结束条件设计

## 7. 易错点辨析

### 易错 1：`switch` 必须配 `break`

不完全对。

新语法里如果 `case` 直接 `return`，不需要 `break`。

### 易错 2：sentinel value 可以和普通输入值重合

不推荐。

sentinel 必须是“保留值”，否则会把正常数据误判成结束信号。

### 易错 3：`while` 和 `do-while` 没区别

不对。

`do-while` 至少执行一次。

## 8. ⭐ 短路求值 (Short-Circuit / Lazy Evaluation)

`&&` 和 `||` 从左到右求值。一旦结果确定，右侧不再求值。

### `&&` 短路规则

```java
int a = 0, b = 1;
(a > 0) && (b < 2)   // a>0 为 false，直接返回 false，b<2 不求值
(a >= 0) && (b < 2)  // a>=0 为 true，继续求值 b<2 → true
```

### `||` 短路规则

```java
(a >= 0) || (b < 2)  // a>=0 为 true，直接返回 true，b<2 不求值
(a > 0)  || (b < 2)  // a>0 为 false，继续求值 b<2 → true
```

### Sample Paper 高频陷阱：数组越界 + 短路顺序

```java
// ❌ 错误：先访问 a[i]，后检查 i 是否越界
for (int i = 0; a[i] != value && i < a.length; i++) { ... }
// 当 i 超出 a.length 时，a[i] 先执行 → ArrayIndexOutOfBoundsException！

// ✅ 正确：先检查越界，再访问元素（利用短路保护）
for (int i = 0; i < a.length && a[i] != value; i++) { ... }
```

### 易错点

- `&&` 右侧只有在左侧为 `true` 时才求值
- `||` 右侧只有在左侧为 `false` 时才求值
- 数组越界检查必须放在 `&&` 的**左侧**才能利用短路保护
- Sample Paper Q15 直接考此陷阱

## 9. continue 在 for vs while 中的关键差异

### 在 for 循环中

`continue` 后**仍然会执行** "action-after-each-iteration"（即 i++ 部分），然后再判断条件。

```java
int sum = 0;
for (int i = 0; i < 4; i++) {
    if (i % 3 == 0) continue;   // i=0 和 i=3 时跳过
    sum += i;                     // i=1, i=2 时执行 → sum=3
}
// i 仍然正常递增！continue 不会跳过 i++
```

### 在 while 循环中

`continue` 后**直接跳回判断条件**，跳过循环体内 `continue` 之后的一切代码（包括 i++）。

```java
// ❌ 错误写法：continue 跳过了 i++，导致死循环！
int i = 0, sum = 0;
while (i < 4) {
    if (i % 3 == 0) { continue; }  // i=0 时 continue，跳过 i++
    sum += i;
    i++;                           // 永远执行不到！
}

// ✅ 正确写法：在 continue 之前完成递增
int i = 0, sum = 0;
while (i < 4) {
    if (i % 3 == 0) {
        i++;         // 先递增，再 continue
        continue;
    }
    sum += i;
    i++;
}
```

### 结论

- **for** 的 `continue` → 仍然执行 action-after-each-iteration → 安全
- **while** 的 `continue` → 直接跳回条件判断 → 小心跳过递增导致死循环！

## 10. 分号陷阱（高频选择题）

### for 循环后的多余分号

```java
int i;
for (i = 0; i < 10; i++);    // ← 分号 = 空循环体！
{
    System.out.println(i + 4);
}
// 输出：14（循环跑了 10 次后 i=10，然后执行 { } 块，打印 14）
```

### while 循环后的多余分号

```java
int i = 0;
while (i < 10);   // ← 分号 = 空循环体 → 死循环！
{
    System.out.println("i is " + i);
    i++;
}
// 永远不会输出，程序卡死在 while 循环
```

### do-while 的分号是必需的（不是错误）

```java
do {
    // body
} while (condition);   // ← 这个分号是正确且必须的！
```

### 易错点

- `for (...) ;` → 空循环体，分号后面的 `{ }` 是独立块
- `while (...) ;` → 死循环，永远卡住
- `do-while` 的分号不能省略

## 11. ⭐ 浮点数的条件陷阱

**不要用浮点数做相等/不等判断来控制循环！**

```java
// ❌ 危险：可能死循环
double num = 1;
while (num != 0) {
    num -= 0.1;
}
// num 可能永远不精确等于 0！

// ✅ 正确：用不等式
double num = 1;
while (num > 0) {
    num -= 0.1;
}
```

## 12. 布尔表达式简化

### 简化布尔赋值

```java
// ❌ 冗余写法
boolean even;
if (number % 2 == 0) even = true; else even = false;

// ✅ 简洁写法
boolean even = number % 2 == 0;
```

### 避免 if 中的 `== true`

```java
// ❌ 冗余
if (even == true) { ... }

// ✅ 简洁
if (even) { ... }
```

### ⚠️ 常见笔误：`=` 误写为 `==`

```java
// ❌ 危险：赋值运算符 = 使得条件恒为 true
if (even = true) { ... }   // 永远执行！

// ✅ 正确
if (even == true) { ... }  // 或直接用 if (even)
```
